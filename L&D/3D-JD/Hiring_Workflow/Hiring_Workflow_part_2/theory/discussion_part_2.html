1. Blueprint Creation
• You now have clarity on comparing our assessment platform flow, Mettl, and
HackerRank.
• A blueprint is the base/template used to create an assessment.
• Blueprint contains fields such as:
o Skills and topics
o Question type
o Complexity/difficulty
o Number of questions
o Proficiency level
• For KBA assessments, the difficulty mix is a recommendation. The content admin can
modify it.
• For skill-based/custom blueprints, creation is more flexible without the KBA
recommendation restrictions.
• Blueprint should remain requirement-agnostic, so the same blueprint can later be used
for hiring, skilling, or internal requirements.
2. QB Engine / Question Generation
• The QB engine considers the combination of skill + topic + question type + complexity
while generating/selecting questions.
• Question generation multiplier:
o Technical questions: 10x
o Aptitude questions: 20x
• Example: if the blueprint needs 10 technical questions, the QB engine should generate
100 questions.
• Aptitude can use a higher multiplier because the question formats are generally simpler to
generate.
• Technical/coding questions require additional elements such as code skeletons, test
cases, and expected results.
• Questions are cross-checked, and only Approved for Use questions should be available
for assessment creation.
• During assessment creation, the system should select approved and unused questions
according to blueprint parameters.
3. Assessment Creation
Assessment creation starts from the Blueprint Library:
Blueprint Library → Preview Blueprint → Create Assessment → Configure Settings → Schedule
Assessment
• Admin reviews the blueprint section-wise, including skills, topics, question types, and
question counts.
• The current Generate button should be renamed Create Assessment.
• Creating an assessment is not limited to selecting questions. The assessment
configuration/settings are equally important.
4. Assessment Configuration
Important configuration areas discussed:
General settings
• Access window
• Unidirectional navigation
• Pass percentage
Test Integrity
• Full-screen/proctoring-related controls
• Safe Exam Browser/web-browser protection
• Environment/network checks enabled by default where applicable
Publishing Category
• Hiring
• Skilling
• Internal requirements
Publishing category provides loose coupling between blueprint and business requirement. The
same blueprint can therefore support different assessment purposes.
For Hiring, unidirectional navigation should be enabled by default. For other publishing categories,
it can be turned off.
The pass percentage can originate from the blueprint based on proficiency level, such as
PL1/PL2/PL3, but the Assessment Admin should have the flexibility to modify it.
5. Roles
Be very clear about the distinction:
• Content Admin: Primarily responsible for content, question bank, and blueprint-related
activities.
• Assessment Admin: Creates/configures assessments, handles settings, scheduling,
invitations, and operational controls. They do not necessarily need to be technical users.
6. Scheduling & Invitations

7. Settings After Scheduling
• Once an assessment is scheduled, several settings should become locked until
candidates complete the assessment.
• For example, test-integrity settings should not be freely changed after scheduling.
• Access-window behavior differs across platforms and should be captured when comparing
our platform, Mettl, and HackerRank.
8. Duration Extension
For an in-flight assessment, the Assessment Admin can extend the duration when required.
Discussed controls:
• Extension should happen in controlled increments.
• Maximum total extension discussed: 2 hours.
• Maximum number of extensions discussed: 5 times.
• These values/settings should be validated against the actual platform requirements.
9. Accommodation Multiplier
An Accommodation Multiplier is planned/groomed for candidates requiring additional
accommodation.
Possible duration multipliers discussed include:
• 1.5x
• 2x
• 2.25x
This should be configured before publishing/scheduling the assessment and is different from
extending an already in-progress assessment.
